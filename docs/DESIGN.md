# myBookkeeping 产品与工程规范

> 本文档约束本重写项目（`myBookkeeping`）的产品思路、信息架构、UI 与工程约定。  
> 后续改功能 / 写 Agent Skill / 做 UI 时，优先遵循本文，而不是原版 `ezbookkeeping` 的复杂度。

---

## 1. 产品定位

- **个人向精简记账**：快记优先，功能够用即可，不做企业账、多币种、复杂报表。
- **相对原版**：砍掉过重能力，保留账户 / 二级分类 / 标签 / 转账 / 模板 / 周期记账 / 附件 / 高德选点 / AI 辅助。
- **一句话**：首页一眼看到本月收支，一键进入「记一笔」，其余管理都在二级页。

---

## 2. 核心交互原则（必须遵守）

### 2.1 单一记账入口

- **首页只强化一个主 CTA：大圆形「记一笔」**。
- 不在首页并列「还款 / 识别 / 模板」等多个记账入口，避免入口分散。
- 信用卡还款、文字识别、票据识图、模板、快捷分类等，一律放在 **记一笔后续页** 内引导。

### 2.2 引导放在后续页

| 场景 | 正确做法 | 错误做法 |
|------|----------|----------|
| 信用卡还款 | 记一笔主类型选「还款」；账户页可有「去还款」快捷 | 首页再做一个还款主按钮；记一笔顶部再占一个 Chip |
| 文字多笔识别 | 子页 `/transactions/recognize`：输入 → 确认列表 → 直接提交 | 用弹窗塞多笔编辑 |
| 票据识图 | 记一笔页内轻量弹窗，识别后填回当前单笔表单 | 为识图再开首页入口 |
| 新增分类/标签 | 记一笔选择器旁「+」快速创建并选用 | 强制跳出到管理页才能记 |

### 2.3 深度页隐藏主导航

- 记一笔、编辑流水、文字识别子页：**隐藏底栏 / 侧栏**，全屏完成任务后返回。
- 列表 / 统计 / 我的：保留主导航。

### 2.4 确认后再落库（AI 多笔）

- 单笔识图：可填入表单后再由用户点「保存」。
- **多笔文字识别**：必须先出可编辑确认列表，用户勾选后「确认提交」再批量创建；禁止静默入库。

### 2.5 语音

- **暂不做**语音记账（DeepSeek 无 ASR；另接 Whisper 会增加链路复杂度）。优先文字多段识别。

## 3. 信息架构

```
首页 /
  └─ 大按钮 → 记一笔 /transactions/new
       ├─ 文字识别 → /transactions/recognize（多笔确认提交）
       ├─ 票据识图（弹窗，填回单笔）
       ├─ 主类型：收支 | 转账 | 还款；收支下再切支出/收入
       ├─ 模板 Chip
       └─ 表单保存 → 回首页

底栏：首页 | 明细 | 统计 | 我的
我的 → 账户 / 分类 / 标签 / 模板 / 周期 / 设置 /（管理员）用户管理
```

### 3.1a 默认分类与标签

分类预设对齐原版 `ezbookkeeping`（`src/consts/category.ts` + `zh_Hans`），本项目用中文名 + MDI 图标，且为**两级**（一级组 + 二级记账项）。

| 类型 | 一级（摘要） |
|------|----------------|
| 支出 | 餐饮、服饰外貌、居住、交通、通讯、购物、娱乐、教育学习、礼物捐赠、医疗健康、金融保险、其他支出 |
| 收入 | 职业收入、金融投资、其他收入 |

- **新用户**：登录/注册时 `EnsureDefaults` 写入完整树。
- **老用户**：按一级名称补齐缺失二级；若「工资」等已是一级，则跳过「职业收入」整树以免重名。
- **标签**：原版无默认标签；本项目预设：报销、出差、工作、家庭、个人、情侣、大额、待还、礼物、可抵税（按名称补齐）。

### 3.1 交易类型语义

| 类型 | 含义 | 是否计入本月支出/收入 |
|------|------|------------------------|
| expense | 真实消费 | 计入支出 |
| income | 真实收入 | 计入收入 |
| transfer | 账户间挪动（含**信用卡还款**） | **不计入**收支汇总 |

**信用卡还款 = 转账**（银行卡/现金 → 信用卡账户），不是支出。刷卡消费才记支出。记一笔 UI 用主类型「还款」引导（底层仍存 `transfer`）。

**记一笔主类型**：`收支 | 转账 | 还款`。选「收支」时下方再切 **支出 / 收入**（小分段控件）。

**信用卡账单出账 = 只读展示**：根据账单日汇总「本期应还 / 本期已还 / 本期待还」；**还后待还 = 整体待还 − 已出账**（即未出账）；**整体待还 = 已用额度**（可提前还）。本期应还 = max(流水拆分应还, 手填已出账)。还款默认预填「本期待还」；还款页可点「提前还款」预填整体待还。不自动生成流水；还款仍以转账记录为准。

**还款预填**：从账户「去还款」或首页临近还款提醒进入时，金额默认填「本期待还」；若设置了默认账户（非信用），自动选为转出账户。可选「还款分几期」：建议金额 = 待还本金÷期数（余数进本次）+ 利息；利息单独填，计入本次实付。手改金额后不再自动覆盖，可用「按本期待还」重算，或「提前还款」加载整体待还。每期实际还款仍各记一笔转账。

**还款日提醒**：信用账户可填还款日（1–28）。在还款日**前一天或当天**，若本期待还 > 0，首页「记一笔」上方显示提醒标记；点击进入还款页并预填。无欠款不显示。

**账户余额手改（账户管理）**：

| 类型 | 可编辑 | 说明 |
|------|--------|------|
| 现金 / 银行卡 / 其他 | 余额 | 直接改，不生成流水 |
| 信用 | 已用额度、已出账 | 未出账 = 已用 − 已出账；库内余额存为 `−已用`；`creditBilledFen` 存已出账 |

**账户档案与存放**：

| 字段 | 适用 | 说明 |
|------|------|------|
| institution | 银行卡 / 信用 | 开户行或发卡机构 |
| cardNo / holderName | 银行卡 / 信用 | **库内明文**；列表/详情 API 只下发脱敏值；完整值须 `GET /accounts/:id/sensitive`；更新时脱敏串忽略不写回 |
| storageNote | 全部 | 文字描述存放位置（现金抽屉、卡夹等） |
| attachments（AccountID） | 全部 | 位置现场照片；与流水附件共用 Attachment 表 |

手机端账单四格改为「上标签 / 下金额」竖排，金额 `nowrap` + `clamp` 字号，避免数字中间折行。

刷卡也可填分期期数与利息（仅影响账单拆分）。

### 3.2 位置

- 默认：`geoMode=point` 单点定位；进入地图应尽量自动取当前位置并选中。
- 可选：`geoMode=route` 起终点 + 连线（打车 / 公交地铁上下站）。
- 字段：`geoLng/Lat/Name` + 可选 `geoEndLng/Lat/Name`。
- 选点页：地名 `AutoComplete`（防抖）；公交地铁须先标定城市（定位 / 手填必填）再用 `LineSearch` 搜线路选站（**不用** Transfer）；选中 POI/站点时跳过逆地理。
- **最近地点**本地缓存 + 近期流水去重，优先点选，减少高德调用。
- **记账模板**可预设地点；记一笔套用时本地回填，不调高德。
- 城市名本地缓存（`mbk_amap_city`），避免每次重填。

### 3.3 计费规则（全局）

- **入口**：我的 → 计费规则（CRUD）；模板只绑定一条 `fareRuleId`；分类/标签不挂规则。
- **字段**：默认原价（可空）、刷卡折扣、全局立减、免费整天（none/yearly/weekly）、日内时段折扣、金额阶梯、乘次阶梯、法定节假日免费、限定地市、生效期、备注、累计周期（自然月 / 指定日起算）、多优惠策略（prefer / lowest / stack）。
- **原价优先级**：预览时 `baseFen` 覆盖 > 模板金额 > 规则默认原价。地铁等票价不固定时，规则可不填原价。
- **金额阶梯**：区间 `(超过元, 至元]`；基准 `full`=全价×折、`card`=票卡价×折；未命中用票卡折。可配福州式：≤80 票卡、超80~150 全价7折、超150~300 全价5折、超300 回票卡。
- **乘次阶梯**：本趟序号 = 本周期已乘次数 + 1；可配第 N 次免费/折扣/立减。
- **日内时段**：`HH:MM` 窗口 + 可选星期；可免费或打折；支持跨午夜。
- **法定节假日**：数据按年写入 MySQL（`holiday_year_records`）。每年 **12 月第三周（15–21 日）** 自动拉取当年 + 下一年并入库（全年一次）；平时计价/查看只读库，不打远程。管理员可 `POST /holidays/:year/refresh` 手动刷新。`freeOnHoliday` 仅认本地 `holiday=true` 放假日。
- **角色**：`user` / `admin`。注册默认 `user`；`init-user` CLI 创建/重置为 `admin`；启动时若无 admin 则提升 `username=admin` 或最早用户。
- **管理员能力**（入口：我的 → 用户管理，仅 `admin` 可见）：

| 能力 | 说明 |
|------|------|
| 查看用户 | 列表全部注册用户（用户名 / 邮箱 / 角色 / 停用状态 / 注册时间） |
| 改角色 | `user` ↔ `admin`；不能改自己；不能降级/停用最后一个**未停用**的管理员 |
| 停用 / 启用 | `disabled=true` 后无法登录，已有会话立即失效；可再启用 |
| 删除用户 | 级联清空该用户账本数据（账户/流水/模板等），不可恢复；不能删自己 |

  API（均需 admin）：`GET /api/admin/users`；`PUT/DELETE /api/admin/users/:id`。节假日手动刷新仍仅 admin。
- **编辑体验**：表单采用「基础常显 + 优惠模块开关」；关掉的模块保存时清空。新建可用场景起步（仅刷卡折 / 周末免费 / 月累计 / 早间 / 第 N 次），不绑定城市名。节假日列表按节日归组显示区间，避免日期碎片。
- **半途补录**：`cycleSeedFen` / `cycleCountSeed`，绑定当前周期起点，换周期失效。
- **记一笔顺序**：模板 → 计费规则（累计标记）→ 类型/金额…；选规则不强制改金额。
- **金额**：可选「填入建议价」；**手填金额始终为准，保存不重算**；流水只记 `fareRuleId` 供累计。
- **累计**：同用户 + 同 `fareRuleId` 的支出，落在规则周期窗口内合计金额与次数。
- **地市**：轻量缓存城市，不每笔自动定位完整地址。

API：`/fare-rules` CRUD；`POST /fare-rules/:id/preview`（可传 `baseFen` / `rideCount`）；`GET /holidays/:year`；`POST /holidays/:year/refresh`（仅 admin）；`POST /templates/:id/preview-fare`。

## 4. UI 设计规范

### 4.1 视觉语言

- **主色**：松绿 `#1b7f5a`（CSS `--primary`）；支出偏暖橙 `#c45c3e`，收入跟主色。
- **字体**：UI `Noto Sans SC`；金额/标题 `Outfit`（`--font-display`）。
- **表面**：半透明卡片 `surface-card` / 行 `surface-row`，轻阴影，圆角约 14–18px。
- **背景**：浅绿灰渐变氛围（`--bg` / `--bg-accent`），非纯白平板。
- **主题**：支持 light / dark / system；收入支出色可在设置覆盖。

### 4.2 首页布局

1. 顶部：**本月支出 | 本月收入** 等宽两列，中间细分割线（避免不对称大留白）。
2. 中部：**唯一**大圆形「记一笔」FAB（可带轻脉冲），强化入口。
3. 下部：最近流水列表（可滚动占满剩余高度）。

### 4.3 表单页

- 金额字段要大、可扫读。
- 主操作按钮用 `hero-cta` / primary block。
- 次要能力（AI、模板）用 tonal / Chip，不与主保存抢层级。
- 内容多、需多步确认的流程 → **独立子页**，不用 Dialog。
- **窄屏表单（&lt;960px，与底栏断点一致）**：内容多的新建/编辑走路由子页（可系统返回、隐藏底栏 `meta.hideNav`）；宽屏可用 Dialog。已覆盖：账户、分类、周期、模板。**计费规则**字段极多，各端一律走子页。短表单（如标签）可保留 Dialog。
- **附件缩略图可点开放大预览**（全屏遮罩；多图可左右切换；点遮罩 / 关闭 / Esc 退出）。删除按钮需 `@click.stop`，避免误开预览。

### 4.3.1 表单字段间距与说明文案（防遮挡）

Vuetify `variant="outlined"` 的 **浮动 label 骑在上边框**；若上一字段用 `hint` + `persistent-hint`，说明文字会压住下一字段的 label（账户编辑曾出现此问题）。

**必须遵守：**

| 做法 | 说明 |
|------|------|
| Dialog / 密集表单优先 `hide-details` | 去掉组件默认 details 区，避免高度不确定 |
| 字段间距用外层 class（如 `.field` + `margin-bottom: 12–16px`） | 保证 outlined label 不被上下元素侵占 |
| 说明文案用独立 `.field-tip`（或同类段落） | 放在**对应字段下方**，与下一字段保持 ≥12px 间距 |
| **禁止**在连续 outlined 字段上叠用 `persistent-hint` | 除非该字段是本组最后一个，且下方无其它 outlined 控件 |
| 一组相关字段可共用一条 tip | 例如信用「已用 / 已出账 / 未出账」用短 tip，账单日说明另起一条 |

参考实现：`Accounts.vue` 编辑弹窗；同类管理弹窗（分类 / 标签 / 模板）已普遍用 `hide-details` + `mb-3`。

### 4.4 移动优先

- 安全区：`--sat/--sab` 等；高度用 `100dvh` / `--app-height`。
- 桌面 ≥960px：左侧导航轨；移动：底栏。
- 触控目标不小于约 44px。

## 5. 技术栈与目录

| 层 | 技术 |
|----|------|
| 后端 | Go · Gin · GORM · MySQL · Redis Session · MinIO |
| 前端 | Vue 3 · Vite · Vuetify · Pinia · ECharts · 高德 JSAPI |
| AI | DeepSeek Chat Completions（文字 / 识图）；Key 空则关闭 |

```
myBookkeeping/
  backend/          # Go API
  frontend/         # Vue 应用
  deploy/           # docker-compose / 环境示例
  README.md         # 启动与配置
  docs/DESIGN.md    # 本文档
```

### 5.1 后端分层

`cmd/server` → `handler` → `service` → `model` + `database`；附件走 `storage/minio`；配置读 `backend/.env`。

### 5.2 前端约定

- 视图：`src/views/*`；可复用组件：`src/components/*`。
- 状态：`src/stores/*`；HTTP：`src/api/http.ts`（统一 `{ ok, data, error }`）。
- 金额：**库内用分（int64）**；展示用 `fenToYuan` / 录入用 `yuanToFen`。

## 6. AI 能力约定

| 能力 | 路由 / 入口 | 行为 |
|------|-------------|------|
| 单笔文字 | `POST /api/ai/recognize-text` | 返回一笔；偏内部/兼容 |
| **多笔文字** | `POST /api/ai/recognize-text-batch` + 子页 | 返回 `items[]`，前端确认后逐笔 `POST /transactions` |
| 票据识图 | `POST /api/ai/recognize-image` + 记一笔弹窗 | 填入当前表单；可挂附件 |

Prompt 须带上用户当前的账户 / 分类 / 标签名单；信用卡还款语义按 **transfer** 引导。

## 7. 工程与协作约定

1. **改 UI 前先对齐本文 §2 / §4（含 §4.3.1 表单防遮挡）**；不要恢复「首页多入口」或「多笔塞弹窗」。
2. **新功能优先挂到记一笔后续流**，而不是首页再加按钮。
3. 数据库字段变更依赖 GORM AutoMigrate；部署后需重启后端。
4. 不引入语音链路，除非产品明确改口并单独评估 ASR。
5. 文档：启动说明写 `README.md`；产品/UI/流程规范写本文，避免 README 膨胀。
