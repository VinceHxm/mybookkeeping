# myBookkeeping 产品与工程规范

> 本文档约束本重写项目（`myBookkeeping`）的产品思路、信息架构、UI 与工程约定。  
> 后续改功能 / 写 Agent Skill / 做 UI 时，优先遵循本文，而不是原版 `ezbookkeeping` 的复杂度。

---

## 1. 产品定位

- **个人向精简记账**：快记优先，功能够用即可，不做企业账、多币种账户、复杂报表。外币消费只作记录（见 §3.4），不接汇率接口。
- **相对原版**：砍掉过重能力，保留账户 / 二级分类 / 标签 / 转账 / 模板 / 周期记账 / 附件 / 高德选点 / AI 辅助。
- **一句话**：首页一眼看到本月收支，一键进入「记一笔」，其余管理都在二级页。

---

## 2. 核心交互原则（必须遵守）

### 2.1 单一记账入口

- **首页只强化一个主 CTA：大圆形「记一笔」**。
- 不在首页并列「还款 / 识别 / 模板」等多个记账入口，避免入口分散。
- 信用卡还款、文字识别、票据识图、模板、快捷分类等，一律放在 **记一笔后续页** 内引导。

### 2.2 引导放在后续页

| 场景 | 正确做法 | 错误做法 |
|------|----------|----------|
| 信用卡还款 | 记一笔主类型选「还款」；账户页可有「去还款」快捷 | 首页再做一个还款主按钮；记一笔顶部再占一个 Chip |
| 文字多笔识别 | 子页 `/transactions/recognize`：输入 → 确认列表 → 直接提交 | 用弹窗塞多笔编辑 |
| 票据识图 | 记一笔页内轻量弹窗，识别后填回当前单笔表单 | 为识图再开首页入口 |
| 新增分类/标签 | 记一笔选择器旁「+」快速创建并选用 | 强制跳出到管理页才能记 |

### 2.3 深度页隐藏主导航

- 记一笔、编辑流水、文字识别子页：**隐藏底栏 / 侧栏**，全屏完成任务后返回。
- 列表 / 统计 / 我的：保留主导航。

### 2.4 确认后再落库（AI 多笔）

- 单笔识图：可填入表单后再由用户点「保存」。
- **多笔文字识别**：必须先出可编辑确认列表，用户勾选后「确认提交」再批量创建；禁止静默入库。

### 2.5 语音

- **暂不做**语音记账（DeepSeek 无 ASR；另接 Whisper 会增加链路复杂度）。优先文字多段识别。

## 3. 信息架构

```
首页 /
  └─ 大按钮 → 记一笔 /transactions/new
       ├─ 文字识别 → /transactions/recognize（多笔确认提交）
       ├─ 票据识图（弹窗，填回单笔）
       ├─ 主类型：收支 | 转账 | 还款；收支下再切支出/收入
       ├─ 模板 Chip
       └─ 表单保存 → 回首页

底栏：首页 | 明细 | 统计 | 我的
我的 → 账户 / 分类 / 标签 / 模板 / 周期 / 设置 /（管理员）用户管理
```

### 3.1a 默认分类与标签

分类预设对齐原版 `ezbookkeeping`（`src/consts/category.ts` + `zh_Hans`），本项目用中文名 + MDI 图标，且为**两级**（一级组 + 二级记账项）。

| 类型 | 一级（摘要） |
|------|----------------|
| 支出 | 餐饮、服饰外貌、居住、交通、通讯、购物、娱乐、教育学习、礼物捐赠、医疗健康、金融保险、其他支出 |
| 收入 | 职业收入、金融投资、其他收入 |

- **新用户**：登录/注册时 `EnsureDefaults` 写入完整树。
- **老用户**：按一级名称补齐缺失二级；若「工资」等已是一级，则跳过「职业收入」整树以免重名。
- **标签**：原版无默认标签；本项目预设：报销、出差、工作、家庭、个人、情侣、大额、待还、礼物、可抵税（按名称补齐）。

### 3.1 交易类型语义

| 类型 | 含义 | 是否计入本月支出/收入 |
|------|------|------------------------|
| expense | 真实消费 | 计入支出 |
| income | 真实收入 | 计入收入 |
| transfer | 账户间挪动（含**信用卡还款**、理财买入 / 赎回） | **不计入**收支汇总 |
| revalue | 理财账户市值校准（有符号差额，见 §3.6） | **不计入**收支汇总 |

**信用卡还款 = 转账**（银行卡/现金 → 信用卡账户），不是支出。刷卡消费才记支出。记一笔 UI 用主类型「还款」引导（底层仍存 `transfer`）。

**记一笔主类型**：`收支 | 转账 | 还款`。选「收支」时下方再切 **支出 / 收入**（小分段控件）。

**信用卡账单出账 = 只读展示**：根据账单日汇总「本期已还 / 本期待还」；界面不再单独展示「本期应还」（可由已还+待还还原，后端仍用于计算）。**本期待还** = max(0, 账单应还 − 已还)；手填「已出账」仅在尚未被本期还款覆盖时参与应还兜底。**本期已还清后**，格子改称「剩余已用」（= 已用额度），脚注给出「预计下次出账约还」；勿把「剩余已用」理解成花呗「下期已累计」。未结清时还后待还 = 整体待还 − 已出账；整体待还 = 已用额度（可提前还）。还款默认预填「本期待还」；还款页可点「提前还款」预填整体待还。不自动生成流水；还款仍以转账记录为准。**退款**（记到信用卡的收入）按入账日落在「本期出账日 ~ 下期出账日前」的，视同本期还款计入「本期已还」（`refundAmount` 单独返回，界面标「含退款」）；记退款时时间应填银行记账日。

**存量分期补录（建账/编辑）**：信用账户可维护多条 `installmentPlans`（名称、剩余本金、剩余期数、每期利息、首期出账日）。**不改已用额度**，只参与账单拆分。系统「出账」= 账单日结账，≠ 花呗正在累积的那一期。

- **已出账**：只填银行/花呗「已出账、当前应还」。上期已还清、下期还在累积时填 **0**；花呗「本期已累计」留在未出账，不要填进已出账。
- **本金 / 期数口径**：表单一律只填**尚未出账**的剩余本金与期数（照抄 App「分期待还」）。
- **首期如何入账**：默认「下次出账起」。若上方已出账里另含该分期的一期，选「另有一期已含在已出账」——那一期**不算进**表单本金/期数；存库时自动补回一期（本金 + 均摊一期、期数 + 1，`firstDueOn` = 最近一次出账日），本期应还仍以手填已出账为准。
- **编辑回显**：按今天重新定位，已出账的期数剔除，只展示尚未出账部分；全部出完的计划不再显示。避免旧逻辑「每次编辑把首期出账日挪到最近一期」导致的重复入账。
- 摘要展示：已出账里含的分期（估算）/ 尚未出账分期 / 估下次出账合计，避免「分期好像没进已出账」的错觉。
- **账户页分期明细**：信用卡账单框下可展开「分期中 N 笔」，列出仍有未出账期数的分期（刷卡分期 + 存量分期）：已出账期数 / 总期数、剩余本金、下期入账日与金额、手续费或每期利息、末期月份；刷卡分期可点进流水。全部出完的不再列出。

**还款预填**：从账户「去还款」或首页临近还款提醒进入时，金额默认填「本期待还」；若设置了**默认还款账户**（非信用），自动选为转出账户。可选「还款分几期」：建议金额 = 待还本金÷期数（余数进本次）+ 利息；利息单独填，计入本次实付。手改金额后不再自动覆盖，可用「按本期待还」重算，或「提前还款」加载整体待还。每期实际还款仍各记一笔转账。

**默认账户（账户管理）**：消费 / 还款各只能指向**一个**账户（可同一账户）。在编辑账户开关设置；列表仅对已设默认的卡片整卡高亮 + 右上角书签角标，并显示对应芯片。未设置时卡片无默认标记。

| 标记 | 字段 | 约束 | 用途 |
|------|------|------|------|
| 默认还款 | `defaultAccountId` | 仅非信用 | 收入、转账转出、还款转出、还款提醒预填转出 |
| 默认消费 | `defaultExpenseAccountId` | 任意未归档 | 支出默认账户（可含花呗等信用） |

新建流水时，在「记一笔」切换 支出 / 收入 / 转账 / 还款 会自动切到对应默认账户；该类默认未设置（或已归档）则保持当前选择。编辑已有流水、套用模板、识别结果、带 `fromAccountId` 的还款入口不套默认。

设置页不再配置默认账户。

**还款日提醒**：信用账户可填还款日（1–28）。在还款日**前一天或当天**，若本期待还 > 0，首页「记一笔」上方显示提醒标记；点击进入还款页并预填。无欠款不显示。

**账户余额手改（账户管理）**：

| 类型 | 可编辑 | 说明 |
|------|--------|------|
| 现金 / 银行卡 / 其他 | 余额 | 直接改，不生成流水 |
| 理财 | 市值 | 可直接改（不留记录）；日常用「校准市值」生成 revalue 流水 |
| 信用 | 信用额度、可用额度、已用额度、已出账、存量分期 | 优先填可用（银行常见展示）；已用 = 额度 − 可用，双向联动；未出账 = 已用 − 已出账；库内余额存为 `−已用`；`creditBilledFen` 存已出账；存量分期见上 |

**账户档案与存放**：

| 字段 | 适用 | 说明 |
|------|------|------|
| institution | 银行卡 / 信用 | 开户行或发卡机构 |
| cardNo / holderName | 银行卡 / 信用 | **库内明文**；列表/详情 API 只下发脱敏值；完整值须 `GET /accounts/:id/sensitive`；更新时脱敏串忽略不写回 |
| storageNote | 全部 | 文字描述存放位置（现金抽屉、卡夹等） |
| attachments（AccountID） | 全部 | 位置现场照片；与流水附件共用 Attachment 表 |

手机端账单四格改为「上标签 / 下金额」竖排，金额 `nowrap` + `clamp` 字号，避免数字中间折行。

刷卡也可填分期期数与利息（仅影响账单拆分）。分期可选**首期出账**：「随刷卡」= 按消费日落入的那期账单（消费日 ≤ 账单日记当月，否则下月）；「下期」= 再推后一个账单周期（银行办理分期后首期常从下期账单开始），存为 `installmentDeferCycles`（0–3，界面提供 0/1）。

### 3.2 位置

- 默认：`geoMode=point` 单点定位；进入地图应尽量自动取当前位置并选中。
- 可选：`geoMode=route` 起终点 + 连线（打车 / 公交地铁上下站）。
- 字段：`geoLng/Lat/Name` + 可选 `geoEndLng/Lat/Name`。
- 选点页：地名 `AutoComplete`（防抖）；公交地铁须先标定城市（定位 / 手填必填）再用 `LineSearch` 搜线路选站（**不用** Transfer）；选中 POI/站点时跳过逆地理。
- **最近地点**本地缓存 + 近期流水去重，优先点选，减少高德调用。
- **记账模板**可预设地点；记一笔套用时本地回填，不调高德。
- 城市名本地缓存（`mbk_amap_city`），避免每次重填。

### 3.3 计费规则（全局）

- **入口**：我的 → 计费规则（CRUD）；模板只绑定一条 `fareRuleId`；分类/标签不挂规则。
- **字段**：默认原价（可空）、刷卡折扣、全局立减、免费整天（none/yearly/weekly）、日内时段折扣、金额阶梯、乘次阶梯、法定节假日免费、限定地市、生效期、备注、累计周期（自然月 / 指定日起算）、多优惠策略（prefer / lowest / stack）。
- **原价优先级**：预览时 `baseFen` 覆盖 > 模板金额 > 规则默认原价。地铁等票价不固定时，规则可不填原价。
- **金额阶梯**：区间 `(超过元, 至元]`；基准 `full`=全价×折、`card`=票卡价×折；未命中用票卡折。可配福州式：≤80 票卡、超80~150 全价7折、超150~300 全价5折、超300 回票卡。
- **乘次阶梯**：本趟序号 = 本周期已乘次数 + 1；可配第 N 次免费/折扣/立减。
- **日内时段**：`HH:MM` 窗口 + 可选星期；可免费或打折；支持跨午夜。
- **法定节假日**：数据按年写入 MySQL（`holiday_year_records`）。每年 **12 月第三周（15–21 日）** 自动拉取当年 + 下一年并入库（全年一次）；平时计价/查看只读库，不打远程。管理员可 `POST /holidays/:year/refresh` 手动刷新。`freeOnHoliday` 仅认本地 `holiday=true` 放假日。
- **角色**：`user` / `admin`。注册默认 `user`；`init-user` CLI 创建/重置为 `admin`；启动时若无 admin 则提升 `username=admin` 或最早用户。
- **管理员能力**（入口：我的 → 用户管理，仅 `admin` 可见）：

| 能力 | 说明 |
|------|------|
| 查看用户 | 列表全部注册用户（用户名 / 邮箱 / 角色 / 停用状态 / 注册时间） |
| 改角色 | `user` ↔ `admin`；不能改自己；不能降级/停用最后一个**未停用**的管理员 |
| 停用 / 启用 | `disabled=true` 后无法登录，已有会话立即失效；可再启用 |
| 删除用户 | 级联清空该用户账本数据（账户/流水/模板等），不可恢复；不能删自己 |

  API（均需 admin）：`GET /api/admin/users`；`PUT/DELETE /api/admin/users/:id`。节假日手动刷新仍仅 admin。
- **编辑体验**：表单采用「基础常显 + 优惠模块开关」；关掉的模块保存时清空。新建可用场景起步（仅刷卡折 / 周末免费 / 月累计 / 早间 / 第 N 次），不绑定城市名。节假日列表按节日归组显示区间，避免日期碎片。
- **半途补录**：`cycleSeedFen` / `cycleCountSeed`，绑定当前周期起点，换周期失效。
- **记一笔顺序**：模板 → 计费规则（累计标记）→ 类型/金额…；选规则不强制改金额。
- **金额**：可选「填入建议价」；**手填金额始终为准，保存不重算**；流水只记 `fareRuleId` 供累计。
- **累计**：同用户 + 同 `fareRuleId` 的支出，落在规则周期窗口内合计金额与次数。
- **地市**：轻量缓存城市，不每笔自动定位完整地址。

API：`/fare-rules` CRUD；`POST /fare-rules/:id/preview`（可传 `baseFen` / `rideCount`）；`GET /holidays/:year`；`POST /holidays/:year/refresh`（仅 admin）；`POST /templates/:id/preview-fare`。

### 3.4 外币支付与金额待确认

场景：信用卡订阅境外会员，人民币扣款按**卡组织入账日汇率**结算，记账当时拿不到准确金额。

- **外币支付（可选开关）**：仅收支可用。记 `foreignCurrency`（ISO 代码，如 USD）+ `foreignAmount`（外币×100）。`amount` 始终是**实际人民币**，余额与统计只认它。支付汇率 = `amount / foreignAmount`，**不入库、不查接口**，仅展示（列表「USD 20.00 · 7.2350」）。
- **金额待确认（周期可选开关）**：周期规则 `amountPending=true` 时，生成的流水按规则金额（预估）入账并带 `amountPending=true`；外币字段一并带入。预估金额照常影响余额与统计，确认后按实际金额重算。
- **确认方式**：编辑该流水，把金额改成账单金额后保存即清除待确认；勾选「账单还没出，保持待确认」可只改其它字段。
- **提醒**：首页「记一笔」上方与还款提醒并列一枚待确认标记（1 笔直达编辑，多笔进 `/transactions?pending=1`）；明细/最近流水显示「待确认」芯片。
- API：`GET /transactions?pending=1` 只看待确认；流水与周期的读写均带 `amountPending` / `foreignCurrency` / `foreignAmount`（流水 PUT 为整体覆盖，前端须回传）。

### 3.5 团购券（待核销 / 已核销 / 已退款）

场景：团购券先付款、后使用，过期未用平台自动退款。付款当时就记支出，避免遗忘；后续只改状态，不在备注里手写。

- **标记**：仅支出可开「团购券」开关，`voucherStatus` = `pending` 待核销 / `used` 已核销 / `refunded` 已退款，可选 `voucherExpireOn` 过期日。
- **一键核销**：明细行内或编辑页按钮，`pending ↔ used` 互切（`POST /transactions/:id/voucher-status`）。
- **一键退款**：选中待核销/已核销的券 → 弹窗预填原金额、原支付账户、当前时间（信用卡改成银行记账日）→ 后端生成一笔收入（分类「退款」，不存在则自动创建；`refundOfId` 指向原券）并把券标为 `refunded`（`POST /transactions/:id/refund`）。入口：明细行「退款」、券编辑页「退款」、记一笔 → 收入 →「从待核销团购券退款」（列出待核销券，快过期的排前面）。
- **撤销**：删除退款流水 → 原券恢复 `pending`、余额回滚；普通编辑不会改掉 `refunded`。删除原券时退款流水保留，仅解除关联。
- **查询**：明细筛选「团购券：不限 / 所有 / 待核销 / 已核销 / 已退款」（`GET /transactions?voucher=pending|used|refunded|all`）；行内显示状态芯片与过期提示（3 天内标红）。
- **提醒**：首页标记「N 张团购券快过期」（3 天内到期或已过期的待核销券），点击进入 `/transactions?voucher=pending`。
- 统计口径：原支出照常计入支出，退款计入收入（分类「退款」）。

### 3.6 理财账户（基金 / 股票）

定位：只记「钱的流向」与偶尔校准的市值，**不接行情、不管持仓**（份额、成本价、分笔买入交给券商 / 支付宝）。

- **账户类型** `invest`，计入资产；`institution` 填平台 / 券商。建账时余额填当前市值。
- **买入 / 赎回**：银行卡 ↔ 理财账户的**转账**，不计入收支。
- **分红 / 赎回落袋收益**：可记到理财账户的收入（或直接记到到账的银行卡）；申购费等可记支出。
- **市值校准**：`POST /accounts/:id/revalue { marketValue, happenedAt?, remark? }`，后端以**当前账户余额**为基准算差额，生成一笔 `type=revalue` 流水（`amount` 为**有符号**差额：正=浮盈，负=浮亏，无分类），同时刷新 `lastReconciledAt`。市值与余额一致时不生成流水，只刷新校准时间。
- **revalue 约束**：只能落在理财账户；不能经 `POST /transactions` 创建；编辑（`PUT /transactions/:id`）只能改差额 / 时间 / 备注，不能与其他类型互改；删除即回滚余额。**不计入**收支统计与分类统计。
- **账户明细**：理财账户顶部展示净投入 / 累计收益 / 收益率。净投入 = 建账余额 + 转入 − 转出；累计收益 = 当前市值 − 净投入（含校准、分红收入、手续费支出）；收益率 = 累计收益 ÷ 净投入（简单收益率，不考虑持有时长）。月度分组里校准单列「市值变动」，不混进流入 / 流出。
- **入口**：账户卡片「校准市值」、理财账户明细页按钮；明细里点校准流水弹窗改差额或删除。流水列表 / 首页最近流水里点校准流水跳到该账户明细（记一笔页不承载此类型）。
- 编辑账户时直接改市值不留记录，表单里提示优先用「校准市值」。

## 4. UI 设计规范

### 4.1 视觉语言

- **主色**：松绿 `#1b7f5a`（CSS `--primary`）；支出偏暖橙 `#c45c3e`，收入跟主色。
- **字体**：UI `Noto Sans SC`；金额/标题 `Outfit`（`--font-display`）。
- **表面**：半透明卡片 `surface-card` / 行 `surface-row`，轻阴影，圆角约 14–18px。
- **背景**：浅绿灰渐变氛围（`--bg` / `--bg-accent`），非纯白平板。
- **主题**：支持 light / dark / system；收入支出色可在设置覆盖。

### 4.2 首页布局

1. 顶部：**本月支出 | 本月收入** 等宽两列，中间细分割线。
2. 中部（占满中间剩余高度、内容垂直居中）：
   - **唯一主 CTA**：更大圆形「记一笔」FAB（可带轻脉冲）→ 进入可编辑记一笔页。
   - FAB 下方：**快捷模板**（最多 9 个，三列触控块；与 FAB 留足间距防误触）。点按弹出**二次确认**后再入账（可改选「去编辑」）；缺账户/金额则进记一笔页；记一笔页内模板 Chip **仍保留**，仅填表不落库。
3. 底部：**最近流水**（固定 5 条）贴底展示，不再用空白把列表撑满。

### 4.3 表单页

- 金额字段要大、可扫读。
- 主操作按钮用 `hero-cta` / primary block。
- 次要能力（AI、模板）用 tonal / Chip，不与主保存抢层级。
- 内容多、需多步确认的流程 → **独立子页**，不用 Dialog。
- **窄屏表单（&lt;960px，与底栏断点一致）**：内容多的新建/编辑走路由子页（可系统返回、隐藏底栏 `meta.hideNav`）；宽屏可用 Dialog。已覆盖：账户、分类、周期、模板。**计费规则**字段极多，各端一律走子页。短表单（如标签）可保留 Dialog。
- **附件缩略图可点开放大预览**（全屏遮罩；多图可左右切换；点遮罩 / 关闭 / Esc 退出）。删除按钮需 `@click.stop`，避免误开预览。

### 4.3.1 表单字段间距与说明文案（防遮挡）

Vuetify `variant="outlined"` 的 **浮动 label 骑在上边框**；若上一字段用 `hint` + `persistent-hint`，说明文字会压住下一字段的 label（账户编辑曾出现此问题）。

**必须遵守：**

| 做法 | 说明 |
|------|------|
| Dialog / 密集表单优先 `hide-details` | 去掉组件默认 details 区，避免高度不确定 |
| 字段间距用外层 class（如 `.field` + `margin-bottom: 12–16px`） | 保证 outlined label 不被上下元素侵占 |
| 说明文案用独立 `.field-tip`（或同类段落） | 放在**对应字段下方**，与下一字段保持 ≥12px 间距 |
| **禁止**在连续 outlined 字段上叠用 `persistent-hint` | 除非该字段是本组最后一个，且下方无其它 outlined 控件 |
| 一组相关字段可共用一条 tip | 例如信用「额度 / 可用 / 已用」用短 tip，账单日说明另起一条 |

参考实现：`Accounts.vue` 编辑弹窗；同类管理弹窗（分类 / 标签 / 模板）已普遍用 `hide-details` + `mb-3`。

### 4.4 移动优先

- 安全区：`--sat/--sab` 等；高度用 `100dvh` / `--app-height`。
- 桌面 ≥960px：左侧导航轨；移动：底栏。
- 触控目标不小于约 44px。

## 5. 技术栈与目录

| 层 | 技术 |
|----|------|
| 后端 | Go · Gin · GORM · MySQL · Redis Session · MinIO |
| 前端 | Vue 3 · Vite · Vuetify · Pinia · ECharts · 高德 JSAPI |
| AI | DeepSeek Chat Completions（文字 / 识图）；Key 空则关闭 |

```
myBookkeeping/
  backend/          # Go API
  frontend/         # Vue 应用
  deploy/           # docker-compose / 环境示例
  README.md         # 启动与配置
  docs/DESIGN.md    # 本文档
```

### 5.1 后端分层

`cmd/server` → `handler` → `service` → `model` + `database`；附件走 `storage/minio`；配置读 `backend/.env`。

- **handler 按资源分文件**（同一 `handler` 包）：`account.go` / `transaction.go` / `schedule.go` / `auth.go` / `admin.go` …；`api.go` 只放 `API` 结构体、构造、健康检查与 `parseTimePtr` 等公共辅助。新增接口放进对应资源文件，不再往 `api.go` 堆。
- **请求体复用**：创建与更新字段相同时，抽成 `xxxBody` + `toInput()`（参考 `txBody`、`scheduleBody`），避免加字段时漏改一处。json 标签只出现在 handler 层，service 的 `XxxInput` 不带标签。

### 5.2 前端约定

- 视图：`src/views/*`；可复用组件：`src/components/*`。
- 状态：`src/stores/*`；HTTP：`src/api/http.ts`（统一 `{ ok, data, error }`）。
- 金额：**库内用分（int64）**；展示用 `fenToYuan` / 录入用 `yuanToFen`。
- **页面只做组装**：功能块拆成 `components/*`（双向绑定用 `defineModel`），跨组件的业务逻辑抽成 `composables/useXxx.ts`。同一块 UI 出现两次就抽组件。
- **区块头统一用 `MetaHead`**（图标 + 标题 + 说明 + 右侧插槽放开关/徽标），不要再各自写 `meta-head` 样式。
- 记一笔页现有拆分：`FareRuleSection`（计费规则）、`CreditExtrasPanel` + `useRepaySuggestion`（信用卡分期 / 还款建议）、`ForeignPaymentFields`（外币）、`LocationSection`（地点 + 地图弹窗）、`ReceiptRecognizeDialog`（票据识图）、`QuickNameDialog`（快捷新建分类 / 标签）。

### 5.3 多语言

支持 `zh-CN`（基准）/ `en` / `ja` / `ko`，全部页面已迁移。新增界面文案一律走 i18n，不再写中文硬编码。

- **前端**：`vue-i18n`（Composition 模式）。通用文案在 `src/i18n/locales/*.ts`（`zh-CN.ts` 定义结构，其余语言用 `MessageSchema` 约束）；各页面 / 功能的文案放 `src/i18n/modules/<命名空间>.ts`，文件名即命名空间，一个文件内写全四种语言，用 `const en: typeof zh` + `satisfies LocaleBundle<typeof zh>` 约束，漏键 `npm run build` 直接报错。组件内 `const { t } = useI18n()`；组件外（utils / store / axios）用 `import { t } from '../i18n'`。含链接或加粗的句子用 `<i18n-t>` 插槽，不拆句拼接。避免用 `t` 当循环变量或函数参数名。
- **格式**：日期用 dayjs 本地化格式；金额千分位与紧凑金额（万 / 만 / K）走 `Intl.NumberFormat(currentLocale())`，不手写单位；人民币仍显示 `¥`。
- **语言来源**：登录后以用户设置 `locale` 为准（设置页、登录 / 注册页切换，选中即保存）；未登录或老账号为空时取本地缓存 `mbk_locale` → 浏览器语言 → 中文。
- **后端报错**：前端每个请求带 `Accept-Language`；service 层继续写中文 `errors.New`，`handler.Fail` / 中间件出口用 `i18n.T` 按中文原文查 `internal/i18n/messages*.go`（按领域分文件）翻译，查不到回退中文。原文含数字时写成 `%d` / `%s` 模板。同一原文可在多个文件登记，但译文必须一致（`TestNoConflictingMessages` 检查）。**改中文报错原文须同步改翻译表的键。** 后端兜底的展示文案（统计里的「未分类」、分期默认名、流水页说明等）同样在 handler 出口 `i18n.T`。 前端需要按错误类型分支时用 `FailCode` 返回稳定 `code`（如 `user_disabled`），不要匹配文案。
- **默认分类**：四语名称全部入库（`Category.PresetKey` 为中文预设名，`NameZh/En/Ja/Ko` 为译名，译名源在 `internal/i18n/presets.go`），`Name` 跟随用户界面语言；切换语言时整套重命名，不会多出一套。用户改名后清空四语名、只用自定义名（`PresetKey` 保留，补齐时不会再补回）。老账号未改名的中文默认分类在登录 / 切换语言时按任一语言名称回填。凭证退款用的「退款」分类同样走预设。
- **默认标签**：按注册语言生成一次（`User.PresetLocale`），之后视为用户数据不随语言变化；按名补齐只对中文预设执行。新增分类 / 标签预设须同时加译名，`TestPresetNamesTranslated` 会检查。
- **不翻译**：用户自建数据（账户 / 改名后的分类 / 标签 / 备注等）、法定节假日、高德地名、AI 识别 Prompt。

## 6. AI 能力约定

| 能力 | 路由 / 入口 | 行为 |
|------|-------------|------|
| 单笔文字 | `POST /api/ai/recognize-text` | 返回一笔；偏内部/兼容 |
